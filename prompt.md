# prompt.md

Prompts for building a portfolio that is a room, with [Claude Code](https://claude.com/claude-code)
and three skills. This is what produced [makimum.dev](https://makimum.dev) — the
repository you are standing in.

**What they give you:** a procedural 3D room with a palette you can defend, a
token ramp its screens share, and motion with reasons behind its numbers.

**What they do not:** this exact room. These skills interrogate you before they
write anything. Expect a conversation. That is the reason the output is any good,
and it is also the part most people quit before reaching.

---

## Install once

Inside Claude Code:

```bash
/plugin marketplace add AThevon/genjutsu
/plugin install genjutsu
```

In a terminal:

```bash
npx skills add zanwei/design-dna
```

That is the whole setup. `genjutsu:paint` and `genjutsu:cast` arrive together in
one plugin; `design-dna` is a standalone skill.

**Versions this room was built with:** genjutsu **3.3.0**, design-dna as of
August 2026. Both move — if a prompt below behaves differently from what is
described, check the skill's own changelog before assuming the prompt is wrong.

## Before you paste anything

**Decide what you are not allowed to download.**

Here it is every 3D asset and every texture. That one constraint is why the
chair's mesh fabric became a shader, why the book's page edges are computed from
paper thickness, and why the album art is derived from a hash of the track title.
A room you are allowed to buy models for is a room nobody argues about, and the
arguing is where the quality comes from.

Pick your constraint before you pick your palette. Then paste prompt 1.

## 1 · Art direction

```text
I'm building a portfolio site that is a single 3D room in three.js — a desk, a
monitor, a chair, a window. Every object is generated by code at runtime: no
.glb, no .fbx, no downloaded texture, no image in the bundle. That constraint is
not negotiable, it is the point of the project.

Use genjutsu:paint. Art-direct the room: what it is made of, what time of day it
lives in, what the light does, and what its palette is. I want a design system I
can put in a constants file and defend, not a mood board.

Two things matter more to me than it looking nice:

- The palette has to survive being lit. Albedo and illumination multiply, so if
  the warmth sits in the paint, noon and sunset render the same picture. I want
  the colour to come from the light and the surfaces to stay close to neutral.
- Give me a rule I can turn into a test — something a script can check and fail
  on, so the room cannot drift back into a single hue six commits later.
```

## 2 · Tokens for the screens inside the room

```text
The room has working screens inside it: a monitor and a laptop rendering a small
desktop interface to a canvas, plus a tablet. They need one token ramp, not three
sets of hand-picked greys.

Use design-dna. References: [drop 2–4 screenshots or URLs of interfaces whose
feel you want]. Extract the design DNA and give me:

- a token file I can import — ground, surface, card, hairline, text, dim, faint,
  accent — with the measured contrast ratio of each against its own ground, not
  against white
- a type stack and size steps in canvas pixels, plus one scale factor so the same
  layout code serves a 2048x870 ultrawide and a 1536x960 laptop

Everything is drawn with Canvas 2D, not DOM, so the tokens have to be plain
values I can pass to fillStyle and font. No CSS variables, no Tailwind.
```

## 3 · Motion

```text
Now the motion. Use genjutsu:cast.

What moves: the camera flies to an object when you click it, an office chair
spins with real inertia and coasts to a stop, a book turns pages, a lamp fades
on. Give me an interaction thesis with numbers I can put straight into code —
durations, easing, the damping constant for the chair's coast — and then
implement it.

Three rules:

- Reduced motion is a ladder, not a switch. Large travel and rotation go, short
  fades stay. And read the setting live rather than once at load: people turn it
  on when the movement has already made them ill, and they should not have to
  reload to be heard.
- The camera flight is the entire first impression. Past roughly half a second it
  reads as the site thinking, and people click again before it lands.
- No bounce, no elastic. This is a room, not a toy.
```

## When it starts asking questions

It will. `genjutsu:paint` will not skip its brainstorm even if you tell it to,
and that is the single most valuable thing in this whole file.

**Do not answer "modern" or "clean".** Both mean nothing and it will push back.
Say what would feel *wrong* instead — that is easier to name and just as useful.

**Answer the reference question with real links.** Two or three sites you would
be happy to be compared to beats a paragraph of adjectives.

**Read the thesis it writes before you approve it.** One sentence for the look,
one for the motion. Everything downstream is built from those two sentences, so
a vague one costs you a day, not a minute.

## What no prompt gives you

The measuring.

Nearly everything in this project that turned out well came from a measurement
that contradicted a guess:

- The palette was fixed because someone computed the hue spread and found nine
  surfaces inside an 11° band. It is now guarded by a test — `bun run check`
  fails if the room slides back into one hue.
- The frame went from four geometry passes to two because someone counted them
  instead of trusting the on-screen counter, which resets on every internal
  render and was reporting the last fullscreen quad.
- The chair's coast was verified with synthetic time after the browser reported
  2.04 radians for a full turn. The browser was rendering at 400 ms per frame;
  the number was about the environment, not the chair.

Ask for the number. Then ask what it was measured on.
